# ADR-0002：单实例存储选型（SQLite + 本地 Qdrant）

- 状态：已采纳
- 日期：2026-07
- 相关代码：`agentflow/database/sqlite.py`、`agentflow/knowledge/index.py`

## 背景

项目定位为**单机/内网优先的 AI 工作台**，需要存会话、消息、文档元数据、长期记忆、执行记录，
以及向量索引与嵌入缓存。必须满足：零外部服务即可运行、部署简单、数据可备份、可离线开发。

## 决策

- 结构化数据 → **SQLite**（WAL 模式，内建 schema 版本迁移，FTS5 做词法检索）；
- 向量数据 → **Qdrant 本地磁盘模式**（`data/qdrant`），并在配置 `QDRANT_URL` 时可切换为远程服务；
- 嵌入结果 → 本地缓存库，减少重复调用。

## 理由

1. 零依赖即可启动（无需部署数据库服务），契合"本机/单机工作台"定位与开发体验。
2. SQLite 原生支持 FTS5，让"向量 + 词法混合检索"无需引入第二套检索组件。
3. Qdrant 的本地模式与远程模式共用同一客户端接口，未来切换托管实例不需要改业务代码。
4. 三类数据都是文件，备份与迁移就是复制目录（见 runbook）。

## 后果

- 正面：部署最简单、可离线、备份直接、开发调试快。
- 负面：**单写者**，不支持多副本水平扩展；因此 K8s 副本数固定为 1，扩容需先迁移存储。
- 负面：向量索引与关系数据分别落在两处，备份需覆盖两组路径（已在 runbook 中明确）。
- 跟进：当出现多租户/多副本需求时，另立项目迁移到共享数据库（如 Postgres + 远程 Qdrant），
  本 ADR 届时标记为"被替代"。

## 备选方案

- **Postgres + pgvector**：扩展性更好，但部署复杂度显著上升，超出当前定位。
- **纯内存向量索引**：重启即丢，无法满足持久化要求。
- **托管向量数据库**：引入网络依赖与费用，不适合"零外部依赖启动"的目标。
