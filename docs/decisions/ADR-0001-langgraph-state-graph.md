# ADR-0001：用 LangGraph StateGraph 编排多 Agent 工作流

- 状态：已采纳
- 日期：2026-07（架构重构期）
- 相关代码：`agentflow/graph/workflow.py`、`agentflow/agents/base.py`

## 背景

系统需要让多个 Agent（意图分析、规划、检索、搜索、代码执行、反思、回答、记忆）按条件协作，
并且要能表达"失败 → 重新规划 / 重试"这类循环。早期实现是自研的阶段式调度（stage 顺序执行），
难以表达条件分支、循环与状态透传，改动一次流程要改多处。

## 决策

使用 **LangGraph StateGraph** 作为编排层：

- 每个 Agent 是一个节点，输入/输出同一个 `WorkflowState`；
- 条件边（conditional edges）承载路由决策，路由函数独立可测；
- 循环通过条件边回到规划器或执行器表达，并由**集中式终止策略**兜底。

## 理由

1. 状态驱动 + 条件边天然匹配"执行 → 反思 → 继续/重规划"的图结构。
2. 路由逻辑可以写成纯函数（输入 state，输出下一个节点名），便于单测——项目现有
   `tests/test_workflow_routing.py` 覆盖全部路由分支。
3. Agent 只依赖 `run(state)` 契约（`AgentProtocol`），与编排解耦，便于单独替换与测试。
4. 编译后的图可缓存复用，避免每请求重建。

## 后果

- 正面：流程可视化、分支可测、Agent 可插拔；节点级耗时追踪（trace）易于实现。
- 负面：引入了 LangGraph 依赖；节点间通过共享 state 传递，state 字段膨胀需要治理
  （已通过 `graph/state_utils.py` 统一访问器缓解）。
- 跟进：循环上限必须始终存在（见 ADR-0004），否则图可能不收敛。

## 备选方案

- **自研阶段式调度器**：表达力不足，条件与循环逻辑散落，已废弃。
- **纯函数式管道（无图框架）**：可读性好但缺少条件边与可视化，循环需要手写状态机。
- **其他编排框架（如队列/工作流引擎）**：对 LLM 场景的状态透传与调试支持不如前者直接。
